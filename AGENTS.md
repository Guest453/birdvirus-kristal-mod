## Project Layout

- `mod.json` defines metadata, starting map/save state, party, inventory, keybinds, and dev mode. Many `mod.json` changes only apply to new save files.
- `mod.lua` customizes the `Mod` object and is the right place for startup registration, custom events, music volume/pitch tables, and debug options.
- `assets/music/` stores music. `.ogg` is recommended.
- `assets/sounds/` stores sound effects.
- `scripts/battle/enemies/` contains enemy battlers such as `dummy.lua`.
- `scripts/battle/encounters/` contains encounter setup files.
- `scripts/battle/waves/` contains enemy attack waves. A wave id normally matches the file name.
- `scripts/battle/bullets/` contains custom bullet classes. A bullet id normally matches the file name.
- `scripts/data/actors/` contains actor data used for overworld and battle sprites.
- `scripts/data/party/` contains party member data.
- `scripts/data/items/` contains item scripts.
- `scripts/data/spells/` contains spell scripts.
- `scripts/shops/` contains shop scripts.
- `assets/sprites/` contains sprite assets. Bullet sprites are under `assets/sprites/bullets/`.
- Tiled map exports live in `scripts/world/maps/` and tilesets in `scripts/world/tilesets/`.
- `scripts/world/events/` contains custom overworld event classes.
- `scripts/world/scripts/` contains callable world script functions for interactables and script events.
- `scripts/world/cutscenes/` contains world cutscene groups.
- `scripts/world/bullets/` contains `WorldBullet` classes.
- `scripts/hooks/` contains hooks for engine classes. Use hooks only when normal project scripts cannot do the job.

## IDs, Paths, And Lua Rules

- Script IDs default to the file path starting from that script type's subfolder unless an explicit ID is passed to `Class()`.
- IDs are case-sensitive.
- Sprite paths omit `assets/sprites/` and file extension, for example `"bullets/birdvirusSWORD"` for `assets/sprites/bullets/birdvirusSWORD.png`.
- Music paths omit `assets/music/` and file extension.
- Use `local ClassName, super = Class(ParentClass, "optional_id")` for class scripts.
- Always call parent constructors with a period: `super.init(self, ...)`, not `super:init(...)`.
- Return the class at the end of class files.
- Prefer `local` variables. Do not create globals unless the engine requires it.
- Lua uses `nil`, not JSON `null`. Tables are 1-indexed.
- `:` passes `self`; `.` does not.
- Use `DT` or `DTMULT` for manual per-frame motion.
- If overriding `update()` or `draw()`, call `super.update(self)` or `super.draw(self)` unless intentionally replacing parent behavior.

## Text, Actors, Party, Items, Shops, And Spells

- Use Kristal text commands from the writing-text guide, such as `[color:]`, `[font:]`, `[style:]`, `[shake:]`, `[wave:]`, `[image:]`, `[wait:]`, `[voice:]`, `[face:]`, `[react:]`, `[miniface:]`, and shop `[emote:]`.
- Use `\n` for forced line breaks and short `[wait:5]`-style waits after punctuation when matching DELTARUNE-like dialogue pacing.
- Actors are visual data templates, not stage objects. Actor files extend `Actor` and live in `scripts/data/actors/`.
- Actor `width` and `height` should match the intended sprite size because they affect centering. Actor `hitbox` affects overworld collision.
- Actor `path` is relative to `assets/sprites/`; `default` is relative to `path`.
- Use actor `animations`, `offsets`, `portrait_path`, `voice`, `talk_sprites`, `miniface`, and `soul_offset` for polish when needed.
- Party members extend `PartyMember`, live in `scripts/data/party/`, and usually call `self:setActor(...)`.
- Party data owns stats, health, equipment, learned spells, soul color/priority, menu icons, attack sprites, and battle offsets.
- Items extend `Item`, `HealItem`, `TensionItem`, or equipment item classes and live in `scripts/data/items/`.
- Set item `type`, `target`, and `usable_in` intentionally. Use `Game.inventory:tryGiveItem(item_id)` when giving items.
- Shops extend `Shop`, live in `scripts/shops/`, register stock with `self:registerItem(...)`, and register dialogue with `self:registerTalk(...)` / `self:registerTalkAfter(...)`.
- Spells extend `Spell`, live in `scripts/data/spells/`, and put battle effects in `Spell:onCast(user, target)`.
- For overworld spells, implement `hasWorldUsage(chara)` and `onWorldCast(chara)` and ensure config supports overworld TP if needed.

## Maps, Events, And Cutscenes

- Use Tiled for maps. Save `.tmx` files under `scripts/world/maps/` and export them as `.lua` in the same folder.
- Save `.tsx` tilesets under `scripts/world/tilesets/` and export them as `.lua` in the same folder.
- Store tileset images under `assets/sprites/tilesets/`.
- Typical map tile size is `40x40`, while tileset source tiles may be `20x20` to match DELTARUNE's 2x scale.
- The default spawn marker should usually be named `spawn`.
- Prefer transition `marker` properties over raw `x`/`y` properties because markers are easier to maintain.
- Layer names are case-sensitive. Common layers include `objects`, `objects_party`, `controllers`, `markers`, `collision`, `enemycollision`, `paths`, `battleareas`, `blockcollision`, and tile layer `battleborder`.
- Map properties include `name`, `music`, `keepmusic`, `light`, and `border`.
- Custom events extend `Event`, live in `scripts/world/events/`, receive Tiled object `data`, and read custom properties from `data.properties`.
- Tiled cannot directly define arrays; Kristal often uses numbered property patterns such as `text1`, `text2`, or `map1`, `map2`.
- Built-in events include `interactable`, `script`, `chest`, `savepoint`, `transition`, `npc`, `enemy`, `setflag`, `forcefield`, `warpdoor`, `mirrorarea`, `pushblock`, `tilebutton`, and others documented in using-events.
- World scripts live in `scripts/world/scripts/` and return a function. Interactable/NPC scripts receive `event`, `player`, and `facing`; script events receive `event` and `player`.
- World cutscene groups live in `scripts/world/cutscenes/<group>.lua` and return a table of functions.
- A cutscene function receives `cutscene` and usually `event`; start IDs like `group.name` from Tiled or call `Game.world:startCutscene(group, id, ...)`.
- Use `cutscene:text`, `choicer`, `walkTo`, `slideTo`, `fadeOut`, `fadeIn`, `panTo`, and `startEncounter` as appropriate.
- To end a cutscene early, use `return`. Do not call `cutscene:endCutscene()` directly.
- Do not use cutscenes for minigames, puzzles, or ongoing mechanics. Use events, controller objects, timers, or world scripts instead.

## World Battles, UI, And Hooks

- Battle areas are map regions on the `battleareas` object layer. Entering them enables world battle UI, the overworld soul, and the `battleborder` tile layer.
- `Game.world:setBattle(true)` can force world battle state on, but cannot force it off while inside a battle area.
- World bullets extend `WorldBullet`, live in `scripts/world/bullets/`, and are spawned with `Game.world:spawnBullet(id_or_texture, ...)`.
- World bullets use `self.collider` and `self.damage` similarly to battle bullets.
- Use `Game.world:shouldBulletsHurt()` and `Game.world:inBattle()` when world hazards should only hurt in world battle state.
- UI uses `Component`, `Layout`, and `Sizing` classes. Use `World:openMenu(menu)` for overworld menus so movement is handled correctly.
- Components receive input only when focused with `component:setFocused()`.
- Use hooks only when normal project scripts cannot achieve the behavior.
- Hook files for engine classes go in `scripts/hooks/` and use `HookSystem.hookScript(TargetClass)`.
- Always call the original function through `super.functionName(self, ...)` unless intentionally replacing it.

## Kristal Battle Rules

- Waves extend `Wave`: `local MyWave, super = Class(Wave)`.
- Custom bullets extend `Bullet`: `local MyBullet, super = Class(Bullet)`.
- Encounters extend `Encounter` and live in `scripts/battle/encounters/`.
- Enemy battlers extend `EnemyBattler` and live in `scripts/battle/enemies/`.
- Register ACTs in `EnemyBattler:init()` and make `EnemyBattler:onAct(battler, name)` return dialogue text or a table of text.
- If overriding ACT logic, keep Check working by handling it directly or delegating to `super.onAct(self, battler, name)`.
- Use `Wave:init()` for setup fields like `self.time`, `self.arena_width`, or `self:setArenaSize(...)`.
- Use `Wave:onStart()` for runtime logic that needs `Game.battle`, `Game.battle.arena`, or `Game.battle.soul`.
- Use `Wave:update()` for per-frame logic and always call `super.update(self)`.
- Use `self.timer:after`, `self.timer:every`, `self.timer:everyInstant`, or `self.timer:script` for timed attack sequences.
- Spawn a sprite bullet with `self:spawnBullet("bullets/name", x, y)`.
- Spawn a custom bullet with `self:spawnBullet("bullet_id", ...)` where `bullet_id` is the file name in `scripts/battle/bullets/`.
- Movement uses the inherited `physics` table: `speed`, `direction`, `speed_x`, `speed_y`, `gravity`, `spin`, and `match_rotation`.
- `physics.direction` uses radians. `0` is right, `math.pi / 2` is down, `math.pi` is left, `3 * math.pi / 2` is up.
- If a sprite is drawn facing up by default, align it to movement with `rotation = direction + math.rad(90)`.
- For arena size, prefer `self:setArenaSize(width, height)` in `Wave:init()`. Do not call `Game.battle:setArenaSize`; that method does not exist.
- `Timer` functions use seconds, not frames.
- `self.time = -1` means an infinite wave; call `Wave:setFinished()` or `Game.battle:endWaves()` when ending manually.

## Bullet Collision And Damage

- Kristal battle bullets use `self.collider`, not overworld/event hitbox helpers.
- For custom bullet collision, set a collider directly, for example `self.collider = Hitbox(self, 2, 2, self.width - 4, self.height - 4)`.
- If a wave may have no attacker, or if damage must be explicit, set `self.damage` on the bullet.
- `Bullet.damage` defaults from the attacker when available, but explicit `self.damage = 20` is safer for custom hazard bullets.
- Do not override `onDamage` unless changing damage behavior. If overriding and normal damage should still happen, call `super.onDamage(self, soul)`.
- Do not use `setHitbox(...)` for battle bullet damage unless you have confirmed the class supports it in this Kristal version.

## Wave Selection

- Basic enemy wave pools use `self.waves = { "wave_id" }` in an `EnemyBattler`.
- For scripted boss-like order, override `EnemyBattler:selectWave()`.
- If overriding `selectWave`, set and return the selected wave when exact attacker tracking is needed: `self.selected_wave = "wave_id"; return self.selected_wave`.
- Falling back to `return super.selectWave(self)` is fine after scripted waves are exhausted.
- `getNextWaves()` must return a table. `selectWave()` returns a single wave id or nil.

## Current Battle Content Notes

- The main enemy is `scripts/battle/enemies/dummy.lua`, currently repurposed as the bird/virus enemy.
- The dummy actor's idle alternates `birdvirus-001.png` and `birdvirus-002.png` at one second per frame; both are 64x64. `birdvirus-003.png` is intentionally unused.
- Birdvirus has a floating idle effect and afterimage trail implemented directly in `scripts/battle/enemies/dummy.lua`.
- Knife/sword attacks use the 64x64 `assets/sprites/bullets/birdvirusSWORD.png` and custom bullets such as `chargedknife` and `cornerknife`. Its handle is on the right and blade points left, so align it to movement with `rotation = direction + math.pi`. Visible pixels occupy x=9..59/y=13..48, so use origin `(34,31)` and roughly `0.75x` scale rather than centering/scaling the whole canvas.
- Knife attacks are intentionally scripted over multiple turns: `knifedance`, `knifedancering`, `knifedancefast`, and `cornerknives`.
- When tuning attacks, keep them readable and fair. The user specifically wants difficult-looking patterns that are not impossible.
- Knife/sword attacks should charge first, then dash very fast.
- Knife waves were shortened to 8 seconds unless the user changes that requirement again.
- Knife waves should start with one sword at a time, then escalate with more swords.
- Sword trails should look like sword afterimages, not random circles.
- Arena resize normally happens only on the first attack. Explosion-based waves (`giant_bomb`, `virus_explosions`, and `virus_cross_explode`) are an explicit exception and must use an expanded 300x190 arena.

## Current Implemented Systems

- Spawn-time party choice is implemented by `scripts/hooks/World.lua` and `scripts/world/cutscenes/room1.lua`.
- On first load of `room1`, `room1.choose_party` lets the player choose `Kris`, `Ralsei`, or `Noelle` as leader, then sets party to selected leader + Susie.
- The selector is gated by `Game:getFlag("birdvirus_party_selected")`; reset this flag to see the chooser again on an existing save.
- If Noelle is chosen, the code tries to add built-in spell `iceshock` or `ice_shock` if that spell exists in the registry.
- `mod.lua` adds an ACT button to Susie after Birdvirus unlocks `Unvirus`, because Susie's action box may not have ACT at battle start.
- Fake-death timing is routed through `scripts/battle/encounters/dummy.lua:getDialogueCutscene()`, so it plays after player actions finish, not inside the hit callback.
- Normal fake death is HP-capped in `Dummy:hurt()` before the engine defeat/run-away path can run.
- Normal fake-death cutscene is `scripts/battle/cutscenes/dummy.lua:fake_death`.
- Normal fake death restores Birdvirus, removes Kris from `Game.battle.party`, removes Kris's action box, leaves Susie alone, unlocks `Unvirus`, and forces `virus_explosions` as the next wave.
- `Unvirus` is a Susie ACT unlocked only after normal fake death. It fills a dedicated meter by exactly 25% per use, weakens future damage by 15% per use, spawns a small pitched-up explosion, and deals 15 damage.
- The Unvirus meter uses `assets/sprites/birdvirus ui/birdvirustpbar.png` (38x200). `scripts/objects/birdvirus_tp_bar.lua` renders it as battle-level UI at the right edge, with a dim full silhouette and a normal-color copy clipped bottom-to-top to preserve the pointed shape.
- At 100% Unvirus, Birdvirus becomes a non-attacking normal `Bird`, switches to the clean static `birdvirus-001` sprite, loses its virus trail, reaches 100% MERCY, and can be spared for unique thank-you dialogue.
- Unvirus, its ACT button, and its meter are explicitly unavailable and hidden on the Noelle/Snowgrave route.
- Noelle IceShock route is detected in `Dummy:isIceShockAction(battler)` by checking current spell action id/name/cast name for `iceshock` or `ice_shock`.
- If Noelle lands a lethal IceShock before fake death is done, `fake_death_type` becomes `noelle_iceshock` and `dummy.noelle_iceshock` cutscene runs instead.
- Noelle route cutscene removes Susie from battle, sets Susie HP to `-5000`, leaves Noelle alone, sets `enemy.noelle_route = true`, resets Birdvirus attack count, gives phase two 12 DEF, and reduces Birdvirus's damage multiplier against the lone Noelle to `0.70`.
- Each IceShock after the Noelle route begins removes exactly 3 Birdvirus DEF, clamped at 0 (`12 -> 9 -> 6 -> 3 -> 0`). Multi-hit processing is guarded so one cast only applies one defense break.
- Post-phase IceShock dialogue is queued through `DummyEncounter:getDialogueCutscene()` and `dummy.noelle_iceshock_followup`, so Noelle and Birdvirus speak after the action finishes.
- Noelle route wave selection loops `virus_box_hunt`, `virus_minigun`, `virus_cross_explode`, and `virus_chase_burst`.
- SnowGrave is detected separately from IceShock by spell id/name/cast name. Any damaging SnowGrave queues `dummy.noelle_snowgrave`, even if Birdvirus already completed the IceShock fake-death phase or SnowGrave's raw damage would not empty its full HP bar.
- The SnowGrave cutscene restores Birdvirus, disables mercy/Unvirus, gives it a persistent red rage tint/trail, force-plays `ominous` at full volume with sprite/camera shake, and enables `snowgrave_route`.
- SnowGrave rage cycles every Birdvirus attack used by the normal, fallback, and Noelle pools. Compatible attacks are returned as two real simultaneous Wave instances; every box-split attack remains a single wave so its arena split animation stays smooth.
- SnowGrave rage waves and their bullets run at `1.35x` speed. Every spawned bullet is assigned to Birdvirus and receives exactly `+10` damage, including the giant bomb and the two waves that overwrite damage after spawning (`knifedancering` and `knight_boxsplit_rain`).
- `virus_minigun` currently draws a placeholder barrel in code; user plans to provide `minigun.png` later.
- Flowery is a completely separate encounter (`scripts/battle/encounters/flowery.lua`) and does not share Birdvirus state or wave selection.
- The Flowery port is reconstructed from Chapter 5 GML preserved under `extracted/flowey_chapter5/code/`. It uses a mercy-driven seven-phase route with the correct ACT order: Encourage, Blow Away, Spin, Praise, Justice, and Susie's Idea.
- Flowery transforms into the extracted Omega Flowery form at phase 6 and becomes spareable after Susie's Idea.

## Lua/Kristal Pitfalls Seen In This Project

- Lua has `nil`, not JSON `null`. Never pass `nil` to `addMercy`; use `0` if no mercy should be added.
- `self.spare_points` should be a number, not nil/null.
- `Game.battle:setArenaSize(...)` crashed before because that method does not exist in this Kristal version.
- Battle bullet damage required explicit `self.collider = Hitbox(...)` and explicit `self.damage` in this project.
- Do not assume engine source is present locally. Use the Kristal wiki/API or existing mod examples when unsure.
- Lua 5.4.6 was installed with `winget`; use `C:\Users\Cesus\AppData\Local\Programs\Lua\bin\luac.exe -p <files>` for syntax checks if `lua`/`luac` is not visible in the current shell PATH.
- PowerShell is the shell. Use quoted paths and avoid destructive commands.
- `EnemyBattler:heal(...)` can crash from cutscenes if the enemy parent is missing because it tries to spawn a status message. For fake-death healing, direct `enemy.health = enemy.max_health` has been safer.
- Hiding/downing a `PartyBattler` does not remove them from battle UI/actions. To make only one character remain, remove the battler from `Game.battle.party`, remove the matching action box, and reindex boxes.
- `BattleCutscene:setSprite` with a bad/missing sprite can make Susie invisible; the current Susie shocked reaction uses camera/character shake and portrait text instead.
- Do not use a `"shocked"` Noelle portrait/sprite: it is not guaranteed to exist. Noelle-route reactions use her documented default battle sprite via `resetSprite()`, `shakeCharacter(...)`, and an explicit Noelle speaker.
- `Explosion(...)` effects may appear behind the arena unless their layer is raised, e.g. `explosion.layer = BATTLE_LAYERS["above_arena"] or 1000`.

## Asset Guidance

- Keep sprite paths relative to `assets/sprites/` and omit the extension.
- Kristal does not use `.gif` files or spritesheets for normal sprite animations; use separate numbered frames.
- Keep battle bullet sprites small. Oversized PNGs can cover the whole arena/map.
- If resizing PNGs, keep a backup only when useful and mention it.

## Testing

- Keep dev mode enabled during development when possible.
- Best test is in Kristal using dev/debug tools.
- Use the Debug Menu to start encounters and waves when available.
- Use Debug Rendering (`F6`) to inspect collision, events, battle hitboxes, and hidden map objects.
- Test motion/timing changes at both 30 FPS and 60 FPS when feasible.
- If a crash stack trace mentions a mod file, fix the exact line first before broad refactors.
- For battle damage issues, verify the bullet has a collider and damage or an attacker.
